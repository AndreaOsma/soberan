# Security policy

## Supported versions

| Line | Typical use        | Security updates |
| ---- | ------------------ | ---------------- |
| 1.x  | Current main branch | Best effort      |

Only the latest release line on the default branch is actively maintained for this repository.

## Reporting a vulnerability

Please **do not** open a public issue for an unfixed security problem.

1. Prefer **[GitHub Security Advisories](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)** for this repo (*Security* tab → *Report a vulnerability*), if the feature is enabled.
2. If Advisories are not available, contact repository maintainers through a **private** channel they publish for this project (e.g. email in the org profile or security.txt on the deployed site).

Include, when possible:

- Affected area (frontend, API, dependency).
- Steps to reproduce and severity (confidentiality / integrity / availability).
- Version or commit you tested.

We will aim to acknowledge within a few days; timelines depend on maintainer availability.
